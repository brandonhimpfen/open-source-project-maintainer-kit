# Release Checklist

Use this checklist as a starting point and adapt it to the project's release process.

## Before release

- [ ] Confirm the intended release scope.
- [ ] Review unresolved release-blocking issues.
- [ ] Confirm required tests and automated checks pass.
- [ ] Review dependency changes.
- [ ] Review security-related changes and unresolved security reports as appropriate.
- [ ] Update user-facing documentation.
- [ ] Update examples and configuration references where needed.
- [ ] Confirm version identifiers are consistent.
- [ ] Update the changelog or release notes.
- [ ] Check for accidentally committed credentials, private information, build artifacts, or unrelated files.
- [ ] Confirm licensing and attribution files remain accurate for included third-party material.

## Release

- [ ] Create the release commit or approved release branch.
- [ ] Create the version tag using the project's convention.
- [ ] Build release artifacts using the documented process.
- [ ] Verify artifact names and versions.
- [ ] Perform applicable integrity or signing steps.
- [ ] Publish through the project's approved distribution channels.
- [ ] Publish release notes.

## After release

- [ ] Verify the published release can be obtained as expected.
- [ ] Perform a basic installation or usage check where practical.
- [ ] Confirm documentation points to the current release.
- [ ] Announce the release through appropriate project channels.
- [ ] Record known issues.
- [ ] Create follow-up issues for deferred work.
- [ ] Update the development version or milestone if the project uses one.
