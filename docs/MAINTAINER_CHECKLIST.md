# Maintainer Checklist

A reusable checklist for routine repository maintenance. Adjust the frequency to match project activity and maintainer capacity.

## Routine review

- [ ] Triage new issues.
- [ ] Review open pull requests.
- [ ] Close or label duplicates and out-of-scope requests.
- [ ] Check automated build and test status.
- [ ] Review dependency update notices.
- [ ] Review documentation reports.
- [ ] Check for accidental disclosure of secrets or private information in recent contributions.
- [ ] Review pending security reports through the project's private process.

## Periodic maintenance

- [ ] Review supported versions.
- [ ] Review stale branches and obsolete automation.
- [ ] Confirm repository links and primary documentation remain accurate.
- [ ] Review repository permissions and privileged access.
- [ ] Confirm security contact information is current.
- [ ] Review contribution and support instructions.
- [ ] Review project dependencies and third-party notices.
- [ ] Check that release procedures still match actual practice.
- [ ] Review issue and pull-request templates.
- [ ] Record material governance or maintenance changes.

## Before a release

Use `RELEASE_CHECKLIST.md`.

## Project health

Periodically ask:

- Is the documented project scope still accurate?
- Is the current maintenance workload sustainable?
- Are support expectations clear?
- Are important decisions recorded?
- Are critical processes dependent on only one person?
- Are users clearly told which versions are supported?

## When pausing or archiving a project

- [ ] Update the README with project status.
- [ ] Explain whether security reports will still be reviewed.
- [ ] Clarify whether new contributions are being accepted.
- [ ] Disable or update automation that should no longer run.
- [ ] Review privileged credentials and infrastructure.
- [ ] Preserve important release and governance records.
