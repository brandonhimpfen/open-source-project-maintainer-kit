# Contributing to [PROJECT NAME]

Thank you for considering a contribution to [PROJECT NAME]. This guide explains the project's contribution process and helps keep proposed changes focused and reviewable.

## Before contributing

Please search existing issues and pull requests before opening a new one. For substantial features, architectural changes, or changes to established behavior, consider opening an issue for discussion before investing significant work.

Do not include passwords, credentials, private information, access tokens, or other secrets in issues, pull requests, examples, logs, or screenshots.

Security vulnerabilities should be reported using the process in `SECURITY.md`, not through a public issue.

## Ways to contribute

Depending on project scope, useful contributions may include:

- bug reports and fixes;
- documentation improvements;
- tests;
- accessibility improvements;
- feature proposals;
- performance improvements; and
- other changes accepted by the maintainers.

## Bug reports

Use the bug report template where available. Provide enough information for another person to understand the problem and, when practical, reproduce it.

## Feature proposals

Describe the problem or need, the outcome you are proposing, alternatives you considered, and any compatibility or maintenance implications you know about.

A proposal does not create an obligation for maintainers to implement or accept it.

## Pull requests

Before submitting a pull request:

- keep the change focused;
- explain what changed and why;
- update relevant documentation;
- add or update tests when appropriate;
- run available project checks; and
- link related issues when applicable.

Maintainers may request revisions before merging. Contributions may be declined when they fall outside project scope, duplicate existing functionality, create disproportionate maintenance burden, or do not meet project requirements.

## Review criteria

Review may consider correctness, security, maintainability, documentation, compatibility, accessibility, testing, project scope, and long-term support requirements.

## Conduct

Participation in project-controlled spaces is subject to `CODE_OF_CONDUCT.md`.

## Contributions and project licensing

By submitting a contribution, you represent that you have the right to submit it. Accepted contributions are expected to be distributed under the licence that applies to [PROJECT NAME], unless the project explicitly establishes another arrangement.

## Questions

For general help and support boundaries, see `SUPPORT.md`.
